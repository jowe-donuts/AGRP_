# Ay, Gamit Ko 'To!

Ay, Gamit Ko 'To! is a campus lost-and-found application. Students can report
lost or found belongings, browse and search item listings, and submit claims
for items they believe are theirs. The project includes a React web interface
and a FastAPI backend with authentication, item, claim, and administration
APIs.

## Features

- User registration and login with JWT-based authentication.
- Lost and found item reporting, browsing, and search.
- A claim workflow for requesting and managing item returns.
- Student and admin views in the web application.
- CLIP-based text and image embeddings for item matching.
- API documentation generated by FastAPI.

## Technology

| Area | Technologies |
| --- | --- |
| Frontend | React, Vite, JavaScript |
| Backend | Python, FastAPI, Pydantic |
| Data and migrations | SQLModel, SQLite by default, Alembic |
| Matching | CLIP and PyTorch |
| Background tasks | Celery; local configuration defaults to an in-memory broker |

The CLIP model is loaded locally by the backend. Model availability and
hardware affect startup and matching performance. If the model cannot load,
the matcher has a zero-vector fallback; verify model loading before relying on
matching results.

## Run locally on Windows

### 1. Install backend dependencies

Run these commands from the repository root in PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

The backend reads configuration from a `.env` file in the repository root.
Create one with local values, for example:

```dotenv
SECRET_KEY=replace-with-a-local-secret
JWT_SECRET_KEY=replace-with-a-long-random-secret
DATABASE_URL=sqlite:///./agp.db
CORS_ORIGINS=http://localhost:5173,http://localhost:8000
CELERY_BROKER_URL=memory://
CELERY_RESULT_BACKEND=cache+memory://
```

Replace the example secrets. Do not use example or default secrets in a
deployed environment, and do not commit real credentials.

### 2. Start the backend

From the repository root:

```powershell
.\start_backend.bat
```

The script runs the Alembic migrations and starts the FastAPI server on port
8000. It expects `.env` and the root `.venv` to exist. The local task
configuration uses in-process execution; Redis is not required for this
default setup.

### 3. Start the frontend

In a second terminal, from the repository root:

```powershell
npm install
npm run dev
```

Open the Vite URL shown in the terminal (normally
`http://localhost:5173`). The frontend API client uses
`http://localhost:8000` by default. To use a different backend URL, set
`VITE_API_URL` in the frontend's Vite environment.

## API and tests

- Interactive API documentation: `http://localhost:8000/docs`
- Alternative API documentation: `http://localhost:8000/redoc`
- Run backend tests: `python -m pytest`
- Lint the frontend: `npm run lint`
- Build the frontend: `npm run build`

The backend test suite is in `tests/`. Run the tests in your environment
before relying on the application; test outcomes and dependencies can vary
between machines.

## Configuration notes

The backend defaults to a local SQLite database (`agp.db`) and allows the
development frontend origin. The settings module also exposes configuration
for JWT expiration, upload size, Celery, CORS, and optional cloud storage.
Review and set these values for your environment before deploying. In
particular, use strong secrets, restrict CORS to trusted origins, and choose
production-ready database, task-queue, and file-storage services as needed.
